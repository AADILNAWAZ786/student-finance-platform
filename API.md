# API reference

The Student Finance REST API, every operation of it. Generated by `datagen/apidoc.py` from the OpenAPI schema the code produces, the requests and responses `demo_workflow` captured from the running application (seed `20261022`, scale `starter`, business date 2026-08-01) and the role table it measured by calling every operation as every role. Apart from this introduction's prose nothing is hand-written; a test re-renders the file from a fresh demo run and fails on any difference.

> Location: at the repository root at the project owner's instruction; the frozen ARCHITECTURE §3 layout places it under `docs/`.

64 operations on 51 paths. Interactive documentation: `/api/docs/` (Swagger UI), `/api/redoc/` (ReDoc); the schema: `/api/schema/`. Business rules: [BUSINESS_RULES.md](BUSINESS_RULES.md); fields: [DATA_DICTIONARY.md](DATA_DICTIONARY.md).

Captured examples are complete responses. Only execution metadata is replaced by `<volatile>`: `code_version`, `finished_at`, `recorded_at`, `sqlite_version`, `started_at`. Requests were sent with a token header, which is not recorded; no credential, cookie or secret appears in this file.

## Basics

| Topic | Rule |
|---|---|
| Base URL | `http://127.0.0.1:8000/api/v1/` with `python manage.py runserver`; every path below includes `/api/v1/`. |
| Content type | Requests and responses are `application/json` (UTF-8). The browsable API also renders HTML for browsers. |
| Authentication | DRF token: header `Authorization: Token <key>`. Session login also works (browsable API, Swagger). Every operation needs an authenticated user except `GET /api/v1/health/`. Without credentials: 401 `NOT_AUTHENTICATED`; with a role that may not call the operation: 403 `PERMISSION_DENIED`. |
| Getting a token | `python manage.py seed_roles --demo-users` creates the five role groups and one `demo_<role>` user per role and prints each user's token (development only). For another user: `python manage.py drf_create_token <username>` (Django REST Framework). Superusers pass every role check. |
| Money | Strings with 2 decimal places, in INR (`"12500.00"`); more than 2 places → 400. |
| Dates | ISO `YYYY-MM-DD`; business dates are in 2026. When a request omits a business date the service uses today's date in `Asia/Kolkata`. |
| IDs | Business IDs in paths and bodies (`STU-000001`, `INV-STU-000001-2026-000001`, …; DATA_DICTIONARY.md §3). |
| Pagination | List endpoints: `?page=` and `?page_size=` (default 50, maximum 500); responses are `{count, next, previous, results}`. |
| Filtering and ordering | The query parameters listed for each list endpoint (django-filter), and `?ordering=`. |
| Financial records | Read and action only: no PUT, PATCH or DELETE on fee schedules, invoices, lines, payments, allocations, refunds or the ledger (405). Changes are new rows: versions, adjustments, deallocations, reversals, events. |

## Errors

Every error uses one envelope:

```json
{
  "error": {
    "code": "ALLOCATION_EXCEEDS_PAYMENT",
    "rule_id": "BR-ALC-01",
    "message": "…",
    "details": {}
  }
}
```

`rule_id` names the business rule (BUSINESS_RULES.md), or is null for generic errors. 400 malformed input or failed validation; 401 not authenticated; 403 role not allowed; 404 unknown ID or route; 405 method not allowed; 409 state conflict (duplicate, illegal transition, group conflict); 422 valid input that breaks a financial rule; 503 health check failing.

## Not available over HTTP

These exist only as management commands (README): full-scale generation (`generate_data --scale full`; `POST /datagen/runs/` is starter-only), `export_data`, `verify_export`, `verify_reproducibility`, `demo_workflow`, `evaluate --out` (the evaluation itself is also `GET .../evaluation/`), `seed_terms`, `seed_roles`, `seed_scholarship_types`. `/admin/` is the Django admin, not part of the API: payment, scholarship and reconciliation records are read-only there and billing records are not registered. There is no import endpoint or command.

**Generate the invoice for an enrollment.**

Prices the enrollment from the fee schedule versions in force on the term's invoice_date (BR-FEE-01). #### `POST /api/v1/payments/{payment_id}/allocate/`

**Allocate a payment to invoice lines.**

AUTO: allocates everything available, oldest invoice due_date first, then line allocation_priority, then line_id (BR-ALC-03), never beyond a line's open amount (BR-ALC-02). The remainder stays unallocated credit (BR-ALC-04). With no open line, or nothing available, nothing is written and `outcome` says why (NO_OPEN_LINES / NO_FUNDS_AVAILABLE): neither is an error. allocated_on defaults to the payment's received_date. MANUAL: `lines` (1–99 distinct FEE or LATE_FEE lines of the same student) and `allocated_on` are required; all-or-nothing; 422 over the payment's available amount (BR-ALC-01) or a line's open amount (BR-ALC-02). Allocations post nothing to the ledger; collection statuses are refreshed. A payment holds at most 99 allocation rows, deallocations included (409 ALLOCATION_LIMIT_REACHED, an approved exception to the 18-code catalogue).

#### `POST /api/v1/reconciliation/runs/`

**Run reconciliation.**

Runs every detector check (ARCHITECTURE §12.1: structural, relationship, temporal, lifecycle, arithmetic, the five required anomaly types, and the BR-BAL-02 identity per student) for every student (scope ALL) or one (scope STUDENT, student_id required) as of as_of_date. A STUDENT run skips the global checks and lists them in summary.skipped_checks. Synchronous. The run is stored RUNNING first; the checks read outside any transaction, so writes committed during the run may be seen part-way (not a snapshot: re-run once they finish); then every finding and the COMPLETED status are written in one transaction. If anything fails, the run is FAILED with no findings and summary.error. Domain data is never changed. Findings: GET /anomalies/?run=.

- Authentication: token or session
- Roles: `platform_admin`
- Status codes: 201, 400, 401, 403

Request body (`application/json`):

| Field | Type | Required | Notes |
|---|---|---|---|
| `scope` | one of `ALL`, `STUDENT` | yes |  |
| `student_id` | string | no | Required iff scope is STUDENT |
| `as_of_date` | string (date) | yes | 2026 business date |

Captured request: `POST /api/v1/reconciliation/runs/`
